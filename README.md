# ベトナムフーディー

日本でベトナムに関するお店・スポットを探そう。日本にあるベトナム料理店を、地図から探せる Web アプリです。

## 使っている技術(すべてシンプル)

| 技術 | 役割 |
| --- | --- |
| HTML | ページの骨組み |
| CSS | 見た目 |
| JavaScript | 地図とピンの動き |
| [Leaflet](https://leafletjs.com/) | 地図を表示するライブラリ(CDN から読み込むのでインストール不要) |
| [Leaflet.markercluster](https://github.com/Leaflet/Leaflet.markercluster) | 近い場所のピンを、数字つきの丸い1つのアイコンにまとめるプラグイン(CDN から読み込み) |
| [OpenStreetMap Japan タイル](https://wiki.openstreetmap.org/wiki/Japan/OSMFJ_Tileserver)(osm-bright-ja) | カラフルな地図画像(タイル)。無料・APIキー不要・日本語表記。出典「© OpenStreetMap contributors」の表示が必要 |

Node.js や npm、ビルド作業は **不要** です。

## フォルダ構成

```
vietnam-restaurant-map/
├── index.html      ← ページ本体(ブラウザで開くファイル)
├── firestore.rules ← Firestore のセキュリティルール(Firebase コンソールに貼り付けて使う。ブラウザでは読み込まれません)
├── storage.rules   ← Firebase Storage のセキュリティルール(今は使っていないので、すべて拒否する内容。詳しくは「写真投稿機能」を参照)
├── css/
│   └── style.css   ← 見た目
├── images/         ← 画像(ロゴ・アイコン・デフォルト画像・店舗画像を置く場所。詳しくは images/README.md)
├── js/
│   ├── i18n.js     ← 言語の切り替え(日本語 / English / Tiếng Việt)の部品
│   ├── data.js     ← お店のデータ(ここに書き足していく)
│   ├── app.js      ← 地図を作ってピンを置くプログラム
│   ├── detail.js   ← 店舗詳細ページ(Tips・件数エリアなど)
│   ├── auth.js     ← ヘッダーのログイン表示(Google / メールアドレス+パスワード)
│   └── auth-modal.js ← ログインのモーダル(Google・メールログイン・新規登録・パスワード再設定)
└── README.md       ← このファイル
```

## 動かし方

`index.html` をダブルクリックしてブラウザで開くだけです。
(地図の表示にはインターネット接続が必要です)

ファイルを編集したら、ブラウザで再読み込み(Cmd + R)すると反映されます。

## お店を追加するには

`js/data.js` に、次の形で1件書き足します。

```js
{
  name: "お店の名前",
  address: {
    ja: "東京都...",
    en: "... Tokyo",
    vi: "... Tokyo",
  },
  lat: 35.0000,   // 緯度
  lng: 139.0000,  // 経度
  prefecture: "東京都",  // 都道府県(絞り込み用)
  area: { ja: "新宿", en: "Shinjuku", vi: "Shinjuku" },  // エリア(絞り込み用)
  dishes: ["フォー", "バインミー"],  // 取り扱い料理の分類(複数OK・絞り込み用)
  image: "images/viet-nhat.jpg",  // 店舗の画像(省略してもOK。省略すると、デフォルト画像が出ます)
  imageSource: "店舗から提供",     // 画像の入手元・利用許可の記録(省略してもOK。画面には出ません)
  imageCredit: "写真提供: ○○店",   // 画像のクレジット(省略してもOK。画像の下に小さく出ます)
  price: { ja: "準備中", en: "Coming soon", vi: "Sắp cập nhật" },  // 価格帯(省略してもOK)
  hours: { ja: "準備中", en: "Coming soon", vi: "Sắp cập nhật" },  // 営業時間(省略してもOK)
  feature: { ja: "特徴", en: "Feature", vi: "Đặc điểm" },  // 省略してもOK
  googleMapsUrl: "https://maps.app.goo.gl/xxxxxxxx",       // 省略してもOK
},
```

- `googleMapsUrl` は、Google マップでお店のページを開き、「共有」→「リンクをコピー」で取得したURLです。書いておくと、店舗詳細ページの「Googleマップで見る」ボタンがそのページを新しいタブで開きます。省略したお店は、店名と住所で Google マップを検索するページが開きます。

- `prefecture` は、`data.js` の上のほうにある `prefectures`(絞り込みボタンの一覧)の `key` と同じ文字(「東京都」「神奈川県」など)で書きます。
- `area` に書いたエリアは、絞り込みボタンに**自動で**並びます(ボタンを別に用意する必要はありません)。
- `dishes` には、そのお店の取り扱い料理の**分類**を複数書けます。使える分類は、`data.js` の `dishTypes` にある **フォー・バインミー・ブン・ご飯もの・バインセオ・春巻き・その他** の7つです(生春巻き・揚げ春巻きは「春巻き」、鍋料理・コース料理は「その他」にまとめます)。絞り込みボタンは、書かれた分類から**自動で**、この順番に並びます。英語・ベトナム語の表示名と、検索用の別名(`aliases`。「生春巻き」で検索すると「春巻き」のお店が見つかる、など)も `dishTypes` にあります。
- `price`(価格帯)と `hours`(営業時間)は、今は画面に表示していません(データだけ残しています)。まだ調べていないお店は「準備中」としています。
- `name` / `address` / `feature` / `area` は、普通の文字列(どの言語でも同じ表示)でも、`{ ja, en, vi }` でも書けます。
- 書いていない言語は、日本語で代わりに表示されます。

## 店舗カードの画像

一覧の店舗カードは、左に画像、右に「店名・📍エリア・🍜主な料理」が並ぶ横長のカードです。地図のピンをクリックしたときのポップアップには、店名・♡・Tips件数・レビュー件数・住所・(特徴)・「詳細を見る」ボタンが出ます。

- 画像は、すべて同じ大きさ(PC は88px、スマホは72px の正方形)にそろえて表示します。縦長・横長の画像は、中央を切り抜きます。
- `image` を書いていないお店は、`images/default-shop.svg`(ベトナム風のイラスト。実際の店舗の写真ではありません)が表示されます。画像の読み込みに失敗したときも、同じ画像に切り替わります。
- **画像は、利用の許可を確認できたものだけ**を使ってください(店舗から提供された画像、自分で撮影した画像など)。Google マップ・食べログ・Retty・Instagram などの画像を、許可なくコピーして使うことはできません。このアプリには、外部のサイトから画像を自動で集める仕組みはありません。
- `image` には、`images/` フォルダの中のファイル名(`images/xxx.jpg`)か、`https://` で始まるURLを書けます。それ以外の書き方(`javascript:` など)は使われません。

## ロゴ

- ヘッダー左のロゴは `images/logo.png`、ブラウザのタブのアイコンは `images/favicon.png`、スマホのホーム画面用は `images/apple-touch-icon.png` です。
- 元のロゴ画像は `images/logo-original.png` に残してあります(ロゴを作り直すときの元データです)。

## データ・画像・地図の方針

- **店舗情報は、自社データです。** 住所などの基本情報は、`js/data.js` に書いたものだけを表示します。Google などの第三者サービスから、API で自動取得して表示することは、していません。
- **画像は、自社のコンテンツです。** 利用の許可を確認したもの(店舗から提供・自分で撮影など)を、`images/` に置いて登録します。写真の投稿は、まだ実装していません(準備中の表示だけです)。レビューの投稿は、下の「レビュー機能」で実装しています。
- **地図は OpenStreetMap + Leaflet だけです。** 地図の背景は、OpenStreetMap のデータをもとにした、OpenStreetMap Japan のタイル(`tile.openstreetmap.jp`)を使っています。地図の右下に、「© OpenStreetMap contributors」と表示しています。Google マップの情報を、地図に重ねて表示することは、していません。
- **CARTO は使っていません。** 無料の CARTO のタイルは、APIキーが無いと透かし文字が入るため、使っていません(そのため、「© CARTO」の表示もしていません。CARTO を使う場合は、あらためて、その表示が必要です)。
- **Google マップは、外部リンクだけです。** 「Googleマップで見る」「ルートを見る」は、ユーザーが押したときに、Google マップのページを新しいタブで開く、ただのリンクです。Google の API は、呼んでいません。
- **通信する相手は、3つだけです。** 自分のサーバー、Leaflet の配布元(`unpkg.com`)、地図タイル(`tile.openstreetmap.jp`)です。住所検索(Nominatim など)は、アプリの中では、使っていません。データを送信する処理(POST など)は、ありません。

## 検索ボックス

ヘッダーのすぐ下の検索ボックスに文字を入力すると、**入力するたびに**、店名・都道府県・住所・エリア・料理名のどれかに部分一致するお店だけが、地図とリストに表示されます(例: 「東京」で東京都内のお店、「横浜」で横浜市のお店)。

- 日本語・英語・ベトナム語のどの表記でも探せます(例: 「フォー」「pho」「Phở」)。
- 大文字/小文字、全角/半角、ひらがな/カタカナ、ベトナム語の声調記号の違いは区別しません(「ふぉー」でも「フォー」が見つかります)。
- スペースで区切ると、**すべての言葉**を満たすお店を探します(例: 「東京 フォー」なら、東京にあって、フォーを扱うお店)。
- スペースなしで続けて入力しても(「東京フォー」「船橋フォー」)、都道府県・エリア・料理の言葉で区切って探します(間に残った「船橋」のような市の名前も、1つの言葉として使います)。区切るのは、そのままではどのお店にも一致しないときだけです(店名の「フォーハノイ」などは、そのまま探します)。
- 下の絞り込みボタン(都道府県・エリア・料理)とは**併用**できます。検索の言葉と、選んでいるボタンの条件を、すべて満たすお店だけが表示されます。

## 一覧の階層表示(都道府県 → エリア → 店舗)と絞り込み(料理)

一覧は、基本は「都道府県 → エリア → 店舗カード」の3階層のアコーディオンです。**料理を選んで絞り込んでいるときも、この階層表示のままです**(選んだ料理のお店だけに、各階層が絞り込まれます)。

- 最初は、都道府県の見出しだけが見えていて(例: 「東京都 (21)」)、エリア・店舗カードは、すべて折りたたまれています。都道府県の見出しをタップすると、その中のエリアの見出しが出てきます。エリアの見出しをタップすると、そのエリアの店舗カードが出てきます。
- **エリアの見出しには、件数に続けて、代表的な店名も1〜2件出ます**(例: 「新宿 (3) - サンプル店、Hasunamuほか」)。3件以上あるときは、先頭2件のあとに「ほか」と付きます。店名が長いときは、見出しが長くなりすぎないよう、途中で省略します(「…」)。都道府県の見出しは、これまで通り件数だけです。
- 都道府県は `data.js` の `prefectures` に書いた順、エリアは、その都道府県で最初にお店が出てくる順に並びます。カッコの中の数は、そのお店の数です。
- **料理で絞り込むと、都道府県・エリアの見出しの件数も、絞り込まれた数に更新されます。** 該当するお店が1件も無い都道府県・エリアの見出しは、階層から消えます(0件のまま出したりはしません)。
- **地図のピンは、一覧の開閉状態に関係なく、いつも全店舗(または、料理で絞り込んだお店)を表示します**(階層をぜんぶ閉じていても、対象のピンはすべて出ています)。
- 都道府県を増やすときは、`prefectures` に1行足して、お店の `prefecture` にその名前を書くだけです。

**検索ボックスに入力した・「♥ お気に入りのみ表示」をオンにした、のどちらか1つでも当てはまるとき**は、階層表示をやめて、条件に合うお店だけが、これまで通りフラットに並びます。料理カテゴリーの絞り込みは、階層表示を維持したまま、各階層を絞り込みます。「🔍スキャンする」は、これらとは別に、フルスクリーンに近い一覧オーバーレイ(階層を使わない、フラットな一覧)で結果を見せます(詳しくは、後述の「🔍スキャンする」ボタンの節)。

- **料理**: フォー・バインミー・ブン・ご飯もの・バインセオ・春巻き・その他。お店の `dishes` に書かれた分類から自動で作られます。
- **スマホ(幅の狭い画面)**: 絞り込みボタン(お気に入り・料理)は「🔎 絞り込み」の見出しの中に折りたたまれます(タップで開閉)。PC では、いつも開いています。
- **× 条件をリセット**: お気に入り・料理・検索のどれか1つでも選んでいる(入力している)ときだけ表示されます。押すと、すべて元に戻り、検索ボックスも空になって、階層表示に戻ります。開いていた都道府県・エリアの状態は、リセットしても残ります。

### スマホ(幅の狭い画面)での一覧の見せ方(PC とは違います)

PC では、一覧(`#shop-list`)と地図が、これまで通り左右に並んで、いつも両方見えています。**スマホでは、地図を大きく使うため、この一覧を、ふだんは表示しません**。

- 何も絞り込んでいない、ふだんの状態では、**地図が画面のほぼ全体**を占め、地図の下部中央に「📋 お店一覧を見る」ボタンだけが浮きます。これを押すと、後述の「🔍スキャンする」と同じ一覧オーバーレイ(`#scan-overlay`)が開き、見出しは「お店一覧」になります。
- **検索ボックスに入力する・「♥ お気に入りのみ表示」をオンにする・料理カテゴリーを選ぶ**、のいずれかで絞り込みが効いた状態になると、スマホでは、**自動的に**この一覧オーバーレイが開きます(`applyFilters` の最後で呼ぶ `syncMobileListOverlay` が判断します)。絞り込みを解除すると、自動的に閉じて、「📋 お店一覧を見る」ボタンだけの状態に戻ります。
- 「🔍スキャンする」で開いたときだけ、見出しは「周辺のお店」になります(それ以外は「お店一覧」)。中身の作り方(カードのデザイン・本物の地図が一覧の下に繋がる仕組みなど)は、まったく同じです。
- PC では、この自動開閉は行われません(検索・お気に入り・料理の絞り込みは、これまで通り `#shop-list` の中で、その場にフラット/階層で表示されます)。「🔍スキャンする」だけは、PC でも、これまで通り一覧オーバーレイを開きます。
- ウィンドウの幅を、スマホ ⇔ PC の境目(600px)をまたいで変えたときも、正しく切り替わります(PC 側になったときに、検索・絞り込みで開いていたオーバーレイは閉じます。スキャンで開いたものは、PC でも表示したままにします)。

## 地図とリストの連動・ピンのまとめ表示

- **お店のピン**: 絵文字「🍽️」を、白地に緑の丸で囲んだ見た目です(一覧の地図・詳細ページの地図、どちらも同じ)。現在地の目印(青い点)や、まとめ表示の丸い数字アイコンとは、別の見た目にしています。
- **ピンのまとめ表示(クラスタリング)**: 近い場所のピンは「📍18」のような丸い数字のアイコンにまとまります(10件以上はオレンジ、30件以上は赤)。丸をクリックすると、その地域が拡大されて、個別のピンが出ます。絞り込みや検索で表示するお店が変わると、まとめ方も自動で計算し直されます。
- **リスト → 地図**: リストのお店をクリックすると、地図がなめらかにそのお店へ移動して、ポップアップが開きます。ピンがまとめ表示の中にあるときは、ズームインして展開してから開きます。
- **地図 → リスト**: 地図のピンをクリックすると、リストのそのお店が「選択中」として強調表示されます(前の選択は解除されます)。階層表示のときは、そのお店の都道府県・エリアの見出しが自動で開きます。選んだお店のカードが、リストの一番上に来るまで、自動でスクロールします。ポップアップを閉じると、選択も解除されます。

## お気に入り

- 一覧のカードと、ピンをクリックしたときのポップアップの両方に、「♡」ボタンがあります。押すと「♥」になってお気に入りに登録され、もう一度押すと解除されます(一覧とポップアップで、状態は連動します)。
- 登録したお気に入りは、ブラウザの **localStorage** に保存され、ページを再読み込みしても残ります。お気に入りの目印は**店名**です(`data.js` の店名を書き換えると、そのお店の登録は外れます)。詳細ページ用の `id` は、お気に入りの目印には使いません。
- 絞り込みの一番上の「♥ お気に入りのみ表示」をオンにすると、お気に入りのお店だけが、地図とリストに表示されます(料理・検索とも併用できます)。オンにすると、一覧は階層表示をやめて、フラットな一覧になります。この「オン/オフ」自体は保存されず、再読み込みするとオフに戻ります。「× 条件をリセット」でもオフに戻ります。
- 注意: localStorage は、ブラウザ・開き方(`file://` と `http://localhost` など)ごとに別々です。開き方を変えると、お気に入りは引き継がれません。

## 「🔍スキャンする」ボタン

**地図の上部中央**に浮かんでいるボタンです(Google マップなどの「このエリアを検索」に近い見た目)。一覧側ではなく、地図に重ねて表示しているので、Leaflet 標準のズームボタン(左上)やピンのクリックの邪魔にはなりません。押すと、**位置情報を使わずに**、その瞬間の**地図の表示範囲**(四隅の緯度経度。Leaflet の `map.getBounds()`)に映っているお店だけに、絞り込みます。

- 押すと、ボタンのすぐ下に「周辺のお店を検索中」と、一瞬だけ表示されます(一瞬で終わる処理ですが、検索していることが伝わるように、少し表示してから結果に切り替えます)。
- 絞り込みの対象(条件に合うお店)自体は、料理カテゴリーの絞り込みと同じ考え方で決まります。
- **結果は、フルスクリーンに近い「一覧オーバーレイ」で表示されます**(`#scan-overlay`)。都道府県・エリアの階層は使わず、条件に合うお店を、フラットに縦一列で並べます。各カードには、写真(投稿された写真の1枚目。無ければ、いつもの一覧と同じデフォルト画像)・店名・エリア・💡Tips件数・⭐レビュー件数を表示します(写真・件数は、カードを出したあと、地図のポップアップと同じしくみで、あとから読み込んで差し込みます)。
- **一覧の下には、いま使っている本物の地図(`#map-wrap`)を、そのまま移動させて置いています**(コピーではありません)。オーバーレイをスクロールしていくと、一覧の最後で、通常の地図画面にそのままつながって見え、スクロールだけで地図の操作に戻れます。閉じるときは、`#content` の元の場所へ戻し、Leaflet に `map.invalidateSize()` で大きさを測り直させます。
- オーバーレイは、上部の「← 戻る」ボタン・「× 条件をリセット」・カードをタップして詳細ページへ移動する(`navigate()` の中で自動的に閉じます)、のいずれかで閉じます。
- 地図を動かしてから、もう一度「🔍スキャンする」を押すと(オーバーレイの下に繋がっている、その本物の地図からでも押せます)、そのときの表示範囲で、一覧オーバーレイの中身を作り直します。
- 「× 条件をリセット」で、このスキャンによる絞り込みも解除され、一覧オーバーレイも閉じて、通常の階層表示(都道府県 → エリア → 店舗)に戻ります。
- 検索ボックスへの入力・料理カテゴリーの絞り込み・「♥ お気に入りのみ表示」は、これまで通りの動き(階層 or フラット表示)のままで、スキャンの一覧オーバーレイとは影響し合いません。

**店舗詳細ページの「📍 現在地からの距離を表示」ボタン(別の機能)**

店舗詳細ページには、これとは別に、ブラウザの位置情報(Geolocation API)で現在地を調べ、そのお店までの直線距離を表示するボタンがあります(一覧の「🔍スキャンする」とは独立した機能で、今回の変更では影響していません)。

- **利用目的の明示**: ボタンの下に、「現在地から近いベトナム料理店を表示するために位置情報を使用します。位置情報は保存されません。」という注記を、許可を求める前から、いつも表示しています(日本語・English・Tiếng Việt)。
- 取得した現在地は、その画面のメモリ上だけで使い、**localStorage・Cookie・URL などには保存しません**。ページを再読み込みすると破棄され、もう一度ボタンを押すと、あらためて取得します。
- 位置情報を取得するときは、ブラウザが覚えている古い位置を使い回さないよう、毎回、新しく取得する設定にしています(`maximumAge: 0`)。
- 位置情報は、`http://localhost` や `https://` のページで使えます。`index.html` をダブルクリックで開いた状態(`file://`)では、ブラウザによっては使えません。その場合は、次のコマンドで簡易サーバーを起動して、http://localhost:8000 を開いてください。

```
cd /Users/ikki/vietnam-restaurant-map
python3 -m http.server 8000
```

**位置情報が使えないときの確認(macOS)**

- 「システム設定 → プライバシーとセキュリティ → 位置情報サービス」で、使っているブラウザ(Google Chrome など)がオンか。
- ブラウザのアドレスバー左のアイコンで、このページの「位置情報」が「許可」か。

失敗の理由は、ブラウザの開発者ツール(F12 → Console)にも出ます。

## Tips 機能(Firebase Firestore)

店舗詳細ページの「💡 このお店のTips」は、みんなの投稿を Firestore に保存して、人数を集計して表示します。

- 詳細ページの店名の下(基本情報の上)に、「💡 Tips ○件」「⭐ レビュー ○件」を表示しています。Tips の件数は、各Tipsの人数の合計です。レビューの件数は、`js/app.js` の `fetchReviewCount`(地図のポップアップでも同じ数を使います)が、Firestore から取得します。
- 選択肢(10個)は `js/i18n.js` の `tipOptions` にあります。`key` は Firestore のフィールド名なので、あとから変えると、これまでの人数と結びつかなくなります。
- Firebase の接続設定と読み書きは、`index.html` の `<script type="module">` に書いてあります(ファイルを直接開いた状態でも動くように、外部ファイルにしていません)。
- 保存先は2つです。① `shops/{店舗ID}/tips/counts`: みんなの集計(フィールド名がTipsのキー(`delicious` など)、値が選んだ人数)。② `shops/{店舗ID}/tipVotes/{ユーザーID}`: そのユーザーの投稿記録(選んだTipsのキーの一覧)。
- 通信に失敗したときは、「Tipsを読み込めませんでした」と表示するだけで、ほかの機能には影響しません。
- **Tipsの追加には、ログインが必要です**(見るだけなら、ログインは要りません)。**1人につき、お店ごとに1回だけ**投稿できます。複数のお店には、自由に投稿できます。投稿済みのお店では、「投稿済みです」と表示して、追加ボタンは出しません。自分が選んだTipsには「✓」が付きます。
- **選択肢を選ぶところまでは、ログインしていなくてもできます。** 「送信する」を押したときに、はじめてログインを求めます。ログインできたら、選んでいた内容を、そのまま送信します(選び直さなくてよい)。ログインをやめた(ポップアップを閉じた)ときは、エラーにせず、選んでいた内容を画面に残したまま、もう一度「送信する」を押せば、また同じ流れになります。
- 「1回だけ」は、画面だけでなく、Firestore のルール(`firestore.rules`)でも守っています。投稿記録のドキュメント名をユーザーIDにして、同じお店には1件しか作れなくし、集計は、投稿記録が同時に作られるときだけ、増やせるようにしています。
- **自分の投稿は、削除できます。** 「投稿済みです」の表示の下に「🗑️ 削除する」ボタンが出ます(他の人の投稿には出ません)。押すと確認メッセージのあと、投稿記録を削除し、各Tipsの人数を -1 します。削除すると、そのお店にまた投稿できる状態に戻ります。
- **Firebase コンソールでの準備が必要です:** ① Firestore Database を作成する(API を有効にする)。② 「ルール」タブに、`firestore.rules` の中身を貼り付けて「公開」する。Tips の選択肢を増やしたり、キーを変えたりしたときは、`firestore.rules` のキーも合わせて直して、公開し直してください。
- **レビュー・写真投稿も、同じ考え方です**(1人につき、お店ごとに1回。写真だけは、枚数の制限がありません)。詳しくは、下の「レビュー機能」「写真投稿機能」を参照してください。

## ログイン機能(Firebase Authentication)

ヘッダーの右側の「ログイン」ボタンを押すと、モーダル(ログインの小さな画面)が開きます。モーダルには、次の4つの画面があります。

- **ログイン**: 「Googleでログイン」ボタンと、メールアドレス+パスワードのログインフォーム。
- **新規登録**: ニックネーム・メールアドレス・パスワードを入力します。ニックネームは、Firestore の `users/{ユーザーID}` に保存します(フィールド `displayName`)。
- **パスワードの再設定**: メールアドレスを入力すると、Firebase から再設定メールが届きます。
- ログインできると、モーダルは自動的に閉じます。ヘッダーには、アイコン・ユーザー名・「ログアウト」ボタンが出ます(スマホでは、ユーザー名は隠して、アイコンだけにしています)。
  - Google でログインしたときは、Google アカウントの名前・アイコンを、そのまま使います。
  - メールアドレス+パスワードでログインしたときは、新規登録のときに入力したニックネームを、Firestore から取ってきて使います(アイコンは、ニックネームの頭文字の丸になります)。

- ログイン表示は `js/auth.js`、モーダルは `js/auth-modal.js`、Firebase Authentication との接続は `index.html` の `<script type="module">`(Tips・Check-in と同じもの)にあります。プロジェクトも同じ `vietnam-foodie` です。
- ログイン状態は、Firebase 標準の仕組みでブラウザに保存されるので、ページを再読み込みしても、ログインしたままです。
- **Tips の追加・チェックインは、ログインが必要です**(1人につき、お店ごとに1回)。それ以外(一覧・検索・地図・お気に入り・Tips や件数の閲覧)は、ログインしていなくても、これまで通り使えます。Tips・Check-in の送信ボタンを押したときに、まだログインしていなければ、この同じログインのモーダルが開きます(選んでいた内容は、ログインできたら、そのまま送信されます)。
- **Google ログインは、`file://`(`index.html` をダブルクリックして開く方法)では動きません。** `python3 -m http.server 8000` で簡易サーバーを起動して、http://localhost:8000 を開いてください(メールアドレス+パスワードのログインは、`file://` でも動きます)。
- Firebase コンソールでの準備:
  - Authentication →「Sign-in method」で「Google」と「メール / パスワード」の、両方を有効にする。
  - 「設定」→「承認済みドメイン」に、公開するドメインを追加する(`localhost` は、はじめから入っています)。GitHub Pages などで公開するときは、そのドメインの追加が必要です。
  - `firestore.rules` の中身を「ルール」タブに貼り付けて「公開」する(`users/{ユーザーID}` のルールが、新しく増えています)。

## Check-in機能(Firebase Authentication・Firestore)

Tipsと同じ考え方で、店舗詳細ページの「レビュー」セクションの下に「📍 このお店にチェックイン」があります。

- **チェックインには、ログインが必要です**(人数を見るだけなら、ログインは要りません)。**1人につき、お店ごとに1回だけ**できます。複数のお店には、自由にチェックインできます。すでにチェックイン済みのお店では、ボタンが「✅ チェックイン済み」になり、押せません。
- **「チェックインする」ボタンは、ログインしていなくても、いつも押せます。** 押したときに、はじめてログインを求めます(Tipsと同じ考え方)。ログインできたら、そのままチェックインします。ログインをやめたときは、エラーにせず、もう一度ボタンを押せば、また同じ流れになります。
- 保存先は2つです。① `shops/{店舗ID}/checkinCount/total`: みんなの合計人数(フィールド `count`)。② `shops/{店舗ID}/checkins/{ユーザーID}`: そのユーザーのチェックイン記録。
- 「1回だけ」は、Tipsと同じく、画面だけでなく Firestore のルール(`firestore.rules`)でも守っています。
- チェックインに成功すると、「Check In Success!」と表示したあと、スマホでは共有シート(Web Share API)が開きます。対応していない環境(主にPC)では、共有用の文字をクリップボードにコピーします。
- **自分のチェックインは、取り消せます。** 「✅ チェックイン済み」の下に「🗑️ 削除する」ボタンが出ます。押すと確認メッセージのあと、記録を削除し、合計人数を -1 します。取り消すと、またチェックインできる状態に戻ります。
- Firebase コンソールでの準備: `firestore.rules` の中身を「ルール」タブに貼り付けて「公開」してください(Tipsのルールに、Check-inの分を追加したものです)。

## レビュー機能(Firebase Authentication・Firestore)

Tips・Check-inと同じ考え方で、店舗詳細ページの「レビュー」セクションに、星評価(1〜5)+コメント(任意)を投稿できます。

- 星は、5つ並んだ★ボタンをタップ/クリックして選びます(必須)。コメントは、500文字までの自由記述(任意)です。
- **レビューの投稿には、ログインが必要です**(読むだけなら、ログインは要りません)。星の選択・コメントの入力は、ログインしていなくてもできます。「投稿する」ボタンは、いつも押せて、押したときに、はじめてログインを求めます(Tips・Check-inと同じ考え方)。ログインできたら、選んでいた星・書いていたコメントを、そのまま投稿します。ログインをやめたときは、エラーにせず、入力した内容を残したまま、もう一度ボタンを押せば、また同じ流れになります。
- **1人につき、お店ごとに1回だけ**投稿できます。すでに投稿済みのお店では、フォームの代わりに「投稿済みです」の表示になります。
- セクションの上部に、平均点と件数を「⭐ 4.2 (12件)」のように表示します。1件も無いときは「まだレビューはありません」です。個々のレビューは、新しい順に、投稿者の名前(Googleログインは、Googleアカウントの名前。メールログインは、新規登録のときに入力したニックネーム)・星・コメントを並べます。
- 保存先は、`shops/{店舗ID}/reviews/{ユーザーID}` の1つだけです(評価・コメント・投稿者名・投稿日時)。Tips・Check-inと違って、レビューは中身をみんなに見せる機能なので、「投稿記録」と「集計」を分けず、このドキュメントを、誰でも読める設定にしています。平均点・件数は、集計専用のドキュメントを持たず、読み込んだレビュー一覧から、画面側で計算します。
- 「1人1店舗1回」は、画面だけでなく、Firestoreのルール(`firestore.rules`)でも守っています。コメントの文字数(500文字まで)・星の範囲(1〜5)・投稿者名の長さも、ルールで検査しています。
- **自分のレビューは、削除できます。** レビューのそばに「🗑️ 削除する」ボタンが出ます(他の人のレビューには出ません)。押すと確認メッセージのあと、削除します。削除すると、平均点・件数が再計算され、そのお店にまた投稿できる状態に戻ります。
- レビュー機能は、店舗のカテゴリー(ベトナム料理、など)に依存しません。店舗IDだけで動くので、将来カテゴリーが増えても、そのまま使えます。
- Firebase コンソールでの準備: `firestore.rules` の中身を「ルール」タブに貼り付けて「公開」してください(Tips・Check-inのルールに、レビューの分を追加したものです)。

## 写真投稿機能(Firebase Authentication・Firestore・Cloudinary)

Tips・Check-in・レビューと同じ考え方で、店舗詳細ページの「📷 みんなの写真」に、写真を投稿できます。画像ファイルは、Firestore ではなく **[Cloudinary](https://cloudinary.com/)**(無料の画像クラウドサービス)に保存します。

- 「みんなの写真」には、最初は「+ 写真を追加する」ボタンだけが表示されています。押すと、投稿フォーム(コンポーザー)が展開され、ボタン自体が「✕ キャンセル」に変わります。キャンセルを押す(または投稿を完了する)と、フォームは閉じて、選んでいた内容(写真・説明文・カテゴリー・同意チェック)はすべて破棄され、最初のボタンだけの状態に戻ります。
- フォームの中では、緑の点線の枠(「+ 写真を追加」)を押すと、ファイル選択(スマホでは、カメラ起動も選べます)が開きます。選んだ画像は、ブラウザ側(canvas)で、長辺 1600px・JPEG に自動で圧縮してから、同じ枠の中にプレビュー表示します(枠の右上の、小さな「✕」で、選び直せます。フォーム全体を閉じる「✕ キャンセル」とは、別の操作です)。
- 枠の下には、説明文(任意・200文字まで)の入力欄、投稿先のお店(店名のみ)の確認カード、カテゴリー(料理・内観・外観・人物・メニューから1つだけ選べる。任意)が並びます。
- **1人が投稿できる枚数に、制限はありません**(Tips・Check-in・レビューと違い、1人1回ではありません)。
- **画像を選ぶところまでは、ログインしていなくてもできます。** 一番下の「投稿する」ボタンを押したときに、はじめてログインを求めます(Tips・レビューと同じ考え方)。ログインできたら、選んでいた画像・説明文・カテゴリーを、そのまま投稿します。
- 投稿された写真は、サムネイルのグリッドで並びます。カテゴリーは、サムネイルの左上に小さなラベルとして、説明文は、写真の下にキャプションとして表示されます(どちらも書いていなければ、出ません)。サムネイルをタップ/クリックすると、拡大表示(ライトボックス)し、そこでもカテゴリー・説明文・投稿者名を確認できます。
- **自分が投稿した写真は、1枚ずつ削除できます。** 押すと確認メッセージのあと、**Firestoreの記録だけ**を削除します。
- 保存先: 画像ファイルは Cloudinary(cloud name: `e1tbcqtm`)に、Cloudinaryが返す画像の公開URL(`secure_url`)・識別子(`public_id`)・投稿者名・投稿日時・非表示フラグ・報告された回数(`reportCount`)・いいねされた回数(`likeCount`)・状態(`photoStatus`。今は `"published"` のみ)・利用規約への同意記録(`termsAgreed`/`termsVersion`/`agreedAt`)・説明文(`description`。任意)・カテゴリー(`category`。任意。`"dish"`/`"interior"`/`"exterior"`/`"people"`/`"menu"` のいずれか)は Firestore(`shops/{店舗ID}/photos/{写真ID}`)に保存します。
- アップロードは、Cloudinaryの「署名不要(Unsigned)アップロード」を、ブラウザから直接(`fetch`でのPOST)行います。API Secret(秘密鍵)は、コードのどこにも書きません。upload preset(`vietnam-foodie-photos`)は、Cloudinary側で「Unsigned」に設定してあり、アップロードできるファイルの種類・サイズの制限は、Cloudinaryのpreset設定側で管理します(アプリ側でも、アップロード前に長辺 1600px・JPEG に圧縮しています)。
- 管理者(`sales@compass-story.com`)は、下の「管理者による非表示機能」と同じ考え方で、写真も非表示にしたり、元に戻したりできます。

### ⚠️ 写真ファイルの削除についての制約

**「削除する」を押しても、Cloudinary上の画像ファイル自体は削除されず、残り続けます。** 削除されるのは、Firestoreの記録(アプリの一覧・拡大表示に使っているデータ)だけです。

これは、Cloudinaryの画像削除APIが、API Secret(秘密鍵)を使った「署名付きリクエスト」を必要とするためです。秘密鍵をブラウザ側のコード(誰でも見られる)に書くことはできないので、このアプリでは、ブラウザから安全に画像ファイルを削除することができません。画像ファイル自体を削除したい場合は、[Cloudinaryの管理画面(Media Library)](https://cloudinary.com/console/media_library)から、手動で削除してください。

### Firebase Storage は、使わなくなりました

写真の保存先をCloudinaryに変更したことにより、**Firebase Storageは、このアプリでは使用していません。** `storage.rules` は、念のため、すべてのアクセスを拒否する内容にしてあります(Firebaseコンソールの Storage の「Rules」タブに、貼り付けて「公開」しておくことをおすすめします)。

- Firebase コンソールでの準備: Firestore の「ルール」タブに、`firestore.rules` の中身(写真の分を含む)を貼り付けて「公開」する。
- Cloudinaryでの準備: ① [Cloudinary](https://cloudinary.com/)の無料アカウントを作る。② 管理画面の「Settings」→「Upload」→「Upload presets」で、新しいpresetを作り、名前を `vietnam-foodie-photos`、Signing Modeを `Unsigned` にして保存する。

### 投稿前の注意事項・同意チェック

投稿フォームには、「📷 写真を投稿する前に」という注意事項(読むだけで、チェックは不要)を、常に表示します。

- 自分が撮影した写真、または自分が投稿する権利を持っている写真を投稿してください
- 他人の写真やWebサイト・SNSなどから無断転載しないでください
- 人物が写っている場合は、プライバシーに配慮し、必要に応じて本人の同意を得てください
- 個人情報など、他人の権利を侵害する情報が含まれていないか、確認してください
- 問題のある写真はレポートされ、非公開・削除される場合があります

**チェックボックスは、「利用規約を確認し、投稿ルールに同意します」の1つだけです**(「利用規約」の文字から、下記の利用規約ページが、新しいタブで開きます)。このチェックが入り、写真を選ぶまで、「投稿する」ボタンは押せません。同意した記録(`termsAgreed: true`・同意した規約のバージョン・同意日時)は、これまで通り、その写真の投稿データと一緒に保存されます。

### 利用規約ページ

`?page=terms` で開ける、独立したページです(店舗詳細ページの `?shop=店舗ID` と同じ、URLパラメータによるルーティングの仕組みを使っています)。中身は `js/i18n.js` の `termsSections` にまとまっていて、サービスについて・投稿できる写真・禁止される投稿・著作権や肖像権(店舗スタッフ・他のお客様が写った写真への注意点を含む)・削除やレポートについてなど、11項目で構成されています。ヘッダーはそのまま残り、一覧・地図は隠れます。「← 一覧に戻る」で、一覧に戻れます。

### プライバシーポリシー・運営者情報ページ

利用規約ページと、まったく同じ仕組み(`?page=privacy`・`?page=about`)で作られた、独立したページです。

- **プライバシーポリシー**(`?page=privacy`): 取得する情報(ログイン情報・投稿情報・位置情報・Cookie・お問い合わせ情報)とその利用目的、Firebaseでのデータ管理、第三者提供、情報の保存期間・削除(ユーザー自身による投稿削除機能があることを含む)、Cookie、お問い合わせ窓口(`sales@compass-story.com`)、変更について、の8項目で構成されています。
- **運営者情報**(`?page=about`): サービス名・運営(Compass Story)・お問い合わせ・サービス概要を、シンプルに掲載しています。お問い合わせのメールアドレスは、`mailto:` リンクになっています。

3ページとも、中身(タイトル・本文・箇条書き)は `js/i18n.js` の `termsSections`/`privacySections`/`aboutSections` にまとまっていて、表示するしくみ(`js/detail.js` の `renderContentPage`)は共通です。ページを追加したいときは、`CONTENT_PAGES`(`js/detail.js`)に1行足して、`js/i18n.js` に文言を追加するだけで、同じ見た目のページが増やせます。

### フッター

ページのいちばん下に、常に表示される、シンプルなフッターがあります(一覧・店舗詳細・利用規約などの、どのページでも表示されます)。「利用規約」「プライバシーポリシー」「運営者情報」の3つのリンクをまとめて置いています。ヘッダーのロゴと同じく、クリックするとページの再読み込みをせずに切り替わります。

### 写真の報告(レポート)機能

各写真に「🚩 この写真を報告」ボタンがあり、**ログインしていなくても**、誰でも報告できます。

- 理由は、「著作権・権利に問題がある」「人物が無断で写っている」「個人情報が含まれている」「店舗と関係のない写真」「不適切な写真」「写真の内容が実際と異なる」「その他」の7つから選びます。
- 報告すると、`shops/{店舗ID}/photos/{写真ID}/reports/{自動生成ID}` に、理由と日時が保存されます(誰が報告したかは記録しません)。あわせて、その写真の `reportCount`(報告された回数)を +1 します。
- **報告されても、自動的に非表示にはなりません。** 管理者(`sales@compass-story.com`)が、店舗詳細ページの写真一覧で、各写真の報告件数(🚩 報告 ○件)を確認し、「報告理由を見る」を押すと、寄せられた理由の一覧を読み込んで確認できます。そのうえで、これまで通り「⚠️ 非表示にする」で対応するかどうかを判断します。
- 報告の記録自体は、投稿した本人を含め、管理者以外は読めません(あとから内容を書き換えたり、削除したりもできません)。
- 店舗側などから写真について指摘があった場合も、同じレポート機能から報告してもらうことで、管理者が内容を確認できます。

### 写真への「いいね」・コメント機能

Tips・Check-inと同じ考え方の「いいね」と、写真の拡大表示(ライトボックス)から使える「コメント」があります。

- **いいね**: グリッド表示・拡大表示の、どちらにも「♡(未いいね)/♥(いいね済み)」ボタンと、件数を表示します。1人1枚につき1回まで(Tips・Check-inと同じ)。もう一度押すと取り消せます。押すところまではログインしていなくてもでき、押した瞬間にログインを求めます(ログインできたら、そのまま反映されます)。保存先は `shops/{店舗ID}/photos/{写真ID}/likes/{ユーザーID}`、合計数は、写真データの `likeCount` フィールドです。いいねは中身が単純な数字のため、管理者による非表示機能は用意していません。
- **コメント**: 拡大表示に「コメント」欄があり、投稿と、新しい順の一覧表示ができます。レビューと違い、**同じユーザーが何度でも投稿できます**(回数の制限なし)。コメントも、入力まではログインしていなくてもでき、「送信する」を押した瞬間にログインを求めます。文字数は300文字までです。自分のコメントは「削除」ボタンで削除できます(削除後も、また投稿できます)。保存先は `shops/{店舗ID}/photos/{写真ID}/comments/{自動生成ID}`。
- 管理者(`sales@compass-story.com`)は、不適切なコメントを「⚠️ 非表示にする」で非表示にでき、「🔁 元に戻す」で戻せます(Tips・Check-in・レビュー・写真本体と、同じ考え方です)。

## 管理者による非表示機能(Firebase Authentication・Firestore)

Tips・Check-in・レビュー・写真の投稿を、管理者だけが非表示にしたり、元に戻したりできます。投稿データ自体は削除しません(投稿者本人による削除は、削除機能として別にあります。下記参照)。

- **管理者は、`sales@compass-story.com` でログインしたアカウントだけです。**(Googleログイン・メールログインの、どちらでログインしていても、管理者として扱われます。)このメールアドレスは `js/auth.js`(画面の出し分け用)と `firestore.rules`(実際の書き込みの許可)の、両方に書いてあります。
- 管理者としてログインすると、店舗詳細ページの各投稿(Tips・Check-in・レビュー・写真それぞれ)に「⚠️ 非表示にする」ボタンが出ます。このボタンは、管理者以外のユーザーには出ません。
- 非表示にすると、Firestore 上のその投稿に `hidden: true` が付きます(投稿の中身は変わりません)。非表示にされた投稿は、一般ユーザーの画面(一覧表示、Tips・Check-inの人数集計、レビューの平均点・件数、写真の一覧)から除外されます。
- 管理者の画面では、非表示にした投稿も引き続き見えます(「🙈 非表示中」の表示付き)。「🔁 元に戻す」ボタンを押すと、再表示できます。
- Tips・Check-inは、投稿の一覧を見るための画面が、これまでありませんでした。管理者としてログインすると、各セクションの下に「🛡 管理者用:◯◯一覧」という、非表示・元に戻すの操作パネルが出ます(投稿者IDの先頭部分と、Tipsなら選んだ内容が並びます)。レビュー・写真は、もともと個々の投稿を一覧表示しているので、その各項目に、直接ボタンが付きます。
- `hidden` フィールドの書き換えは、Firestoreのルール(`firestore.rules`)で、管理者だけに限定しています。一般ユーザーは、自分の投稿であっても、`hidden` フィールドを書き換えられません。投稿の中身(選んだTips・評価・コメント・画像など)も、あとから書き換えることはできません(できるのは、本人による全体の削除と、管理者による `hidden` の切り替えだけです)。
- **一般ユーザー自身による削除機能との違い:** 管理者の「非表示」は、データを残したまま画面から隠すだけです。投稿した本人による「削除」(Tips・Check-in・レビュー・写真それぞれにあります)は、データそのものを消し、また投稿できる状態に戻します。どちらも、Firestoreのルールで、本人または管理者にしか行えないようになっています。
- Firebase コンソールでの準備: `firestore.rules` の中身を「ルール」タブに貼り付けて「公開」してください(Tips・Check-in・レビュー・写真のルールに、管理者用の非表示の分を追加したものです)。
